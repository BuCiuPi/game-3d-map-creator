# Harness Backlog

Use this file when an agent discovers a missing harness capability but should
not change the operating model immediately.

## Template

```md
## Missing Harness Capability

### Title

Short name.

### Discovered While

Task or story that exposed the gap.

### Current Pain

What was hard, repeated, ambiguous, or unsafe? Cite the evidence — link the
`docs/TRACE_LOG.md` rows or name the tasks. An item with no evidence is a
preference, not an improvement.

### Suggested Improvement

What should be added or changed?

### Predicted Impact

What should measurably change once this lands. Write this *before* implementing.

### Risk

tiny | normal | high-risk

### Status

proposed | accepted | implemented | rejected

### Actual Outcome

Added when the item closes. What measurably changed, and how you know. Compare
against Predicted Impact — if the prediction was wrong, say so.
```

See `docs/IMPROVEMENT_PROTOCOL.md` for when to open an item and how to close it.
