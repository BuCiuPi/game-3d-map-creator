01 · Direction

North star

Một content pipeline có ownership rõ: toàn bộ deliverable Addressable assets nằm dưới duy nhất Assets/game.assetbundles/{00_local,01_init,02_partial}; tier folder quyết định availability, layout rule quyết định group/address/label, runtime gateway sở hữu handle, build pipeline tạo bằng chứng, và CI từ chối mọi dependency vi phạm contract.

Học từ HyperEel Core

  • Typed/indexed data tables.
  • UI screen lifetime + child DI scope.
  • Addressables handle ownership.
  • Một build entry point có argument contract.

Không mang sang

  • YGG_Package và sibling/add-on modules.
  • Namespace YGG.* / legacy addresses.
  • Dual build flow và double-build behavior.
  • Cricket-specific groups, labels, whitelist.

Scope clarification

Package exit đã hoàn tất tại 59a0465: template không còn Packages/game-packages, Packages/vfx-packages, file: dependency hoặc internal package mặc định. Project con chỉ mount capability qua Git UPM pin commit khi xuất hiện consumer thật.

04 · Core data

DT / DA contract in the thin template

DT_ và DA_ chỉ là quy ước tên file để tìm kiếm. Semantics thật nằm ở type: DataTable<TRow> là nhiều row cùng schema có stable ID và indexed lookup; DataAsset<TData> là một typed aggregate/config payload. Delivery tier và lifetime không được suy ra từ prefix.

DA · typed aggregate

  • Class XxxDataAsset; file DA_Xxx.asset.
  • Một config, catalog, route map hoặc presentation profile.
  • Runtime chỉ đọc; Editor importer mới được ghi.

DT · typed row table

  • Class XxxDataTable; file DT_Xxx.asset.
  • Row có stable string ID; lazy dictionary index.
  • Null row, empty ID và duplicate ID là validation error.

Template boundary

  • Core chỉ chứa primitive, validation và tests.
  • Không ship DT/DA economy, quest, shop hay stage mẫu.
  • Gateway/scope tải asset sở hữu và release handle.
TierDT / DA placementRule
0000_local/data/bootstrap/{assets,tables}Chỉ boot-critical data ship cùng player. Data cần trước Addressables init phải scene/directly serialized.
0101_init/shared/data/{assets,tables}Shared data cần sau catalog/global init và trước feature entry.
0202_partial/<feature>/data/{assets,tables}Feature-owned data; load/release theo feature scope.

05 · Bootable experience

Minimal UI shell included in the template

Thin core không có nghĩa là màn hình trắng khi boot lỗi. Template giữ đúng bốn UI primitives: hai recovery surfaces concrete trong 00_local và hai post-boot utilities trong 01_init. Mọi UI theo nghiệp vụ nằm trong feature module ở 02_partial.
ClassUIPlacementContract

AFatal/Recovery MessageOverlay00_local/ui/shell/Concrete neutral prefab với Retry/Reload; không phụ thuộc MessagePipe hoặc Addressables instantiate.
BToast01_init/ui/00_shared/Contract + concrete default tối thiểu; chỉ dùng sau khi global DI sẵn sàng.
BGeneric Message/Confirm Dialog01_init/ui/00_shared/Một dialog chung hỗ trợ message và 0–2 actions; game có thể tạo variant để theme.
CFeature popup / feature loading02_partial/<feature>/VIP, shop, quest, liveops, map loading thuộc module nghiệp vụ, không nằm trong core template.
CPopupManager placeholderKhông đưa vào templateKhông có behavior core; tránh thêm manager chỉ để giữ hierarchy.

Tier A strategy

Commit prefab game-owned độc lập và wire trực tiếp vào bootstrap scene. Không dùng package-owned prefab làm base của recovery path.

Tier B strategy

Template cung cấp default đủ chạy; project có thể tạo game-owned variant để đổi presentation mà giữ nguyên contract.

Cricket lesson

Cricket đặt Message/Toast/Loading trong 00_local, nhưng auth failure có thể xảy ra trước global MessagePipe. Template phải tách recovery delivery khỏi post-boot messaging.

08 · Completion criteria

Quality gates

Architecture

  • Một catalog initialization/update owner.
  • Một generated membership owner.
  • Typed scene routes.
  • Không import Cricket/YGG package modules.

Asset correctness

  • Một GUID, một group.
  • Không backward tier reference.
  • Không excluded dependency.
  • Fresh Build Report pass error rules.

Runtime lifecycle

  • Handle có owner và release path.
  • Cancel/fail không leak instance hoặc handle.
  • Không duplicate fetch bất thường trong HAR.
  • Scene unload giải phóng đúng scope.
  • Boot loading và fatal recovery vẫn hoạt động khi catalog/global DI không khả dụng.

Build & CI

  • Không double-build.
  • Build/check lỗi làm process fail.
  • Content-state và reports được lưu.
  • Template sinh mới không chứa legacy names.
